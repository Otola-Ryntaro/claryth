# 030 拡張機能とローカルAPIの相互認証

## 目的
ポート8765を先に確保した別プロセスや、別のChrome拡張機能を正規クライアントとして信用しない。

## 対象外
Windowsコード署名とDB署名。

## 依存
029。

## タスク
- [x] インストール時にユーザー単位のランダム共有トークンを生成する
- [x] トークンをACL制限した設定ファイルへ保存する
- [x] 拡張機能から専用ヘッダーを付与し、APIで定数時間比較する
- [x] `/health`へ固定アプリID、プロトコル版、起動時nonceを追加する
- [x] ランチャーのポート確認を認証済みhealth確認へ置き換える
- [x] 正規・欠落・不正トークンと偽APIのテストを追加する

## 受入条件
共有トークンを持たないプロセスと拡張機能は、healthを除くAPIを利用できない。ランチャーは別サービスが8765を使用中なら明示的に失敗する。

## テスト
401/403、トークンローテーション、ポート競合、拡張再読み込み後の接続を確認する。

## 実装結果
- 認証情報は`.runtime/auth.json`へ保存し、Windows ACLを現在ユーザーのFullControl 1件だけに制限する。
- `install_windows_launcher.ps1 -RotateToken`でローテーションし、`extension/dist`も同時に再ビルドする。
- health以外は`X-Clarith-Token`を必須とし、欠落は401、不一致は403、認証未設定は503を返す。
- 根拠ページは拡張機能が認証付きで取得し、Blob URLとして新しいタブへ表示する。
- ランチャーは`app_id`、プロトコル版、認証結果、起動nonceを確認し、別サービスによるポート占有を拒否する。
