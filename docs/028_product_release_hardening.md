# 028 製品版出荷ハードニング

## 目的
2026年6月13日の製品化・セキュリティレビューで判明した問題を、依存関係のある実装チケットへ分割し、製品版の出荷条件を明確にする。

## 対象外
各チケットの実装詳細と医学レビューそのもの。

## 依存
001から027、および`security_best_practices_report.md`。

## タスク
- [x] 029 未承認データの判定停止
- [ ] 016 レビュー済み候補の本番DB反映
- [x] 030 拡張機能とローカルAPIの相互認証
- [x] 031 DB完全性・署名manifest検証
- [x] 032 API入力境界・CORS・製品モード強化
- [x] 033 依存固定・脆弱性監査・SBOM
- [x] 034 臨床警告UI・アクセシビリティ改善
- [ ] 035 配布・更新・E2E出荷判定

## 実施順
1. 029で未承認データをfail-closedにする。
2. 016で医学レビュー済みデータだけを生成する。
3. 030と031でAPIとDBの真正性を保証する。
4. 032から034で攻撃面と誤使用リスクを下げる。
5. 033と035の成果物・運用・実機試験を満たして出荷判定する。

## 受入条件
029から035および016が完了し、未承認・改変・期限切れのデータでは判定できず、署名済み配布物をクリーンPCへ再現可能に導入できる。

## テスト
各チケットのテストに加え、最終的にPython全テスト、TypeScriptビルド、依存監査、Chrome実機E2E、DB署名検証を実行する。
