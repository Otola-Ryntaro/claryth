# 032 API入力境界・CORS・製品モード強化

## 目的
ローカルAPIの不要な攻撃面とリソース枯渇リスクを減らす。

## 対象外
共有トークン認証と依存更新。

## 依存
030。

## タスク
- [x] 全文字列、配列要素、リクエストボディへ上限を設定する
- [x] 書き込み用Pydanticモデルで未知フィールドを拒否する
- [x] 同時実行数と高コストAPIの呼出頻度を制限する
- [x] CORSを正規拡張Originと必要ヘッダーだけへ限定する
- [x] 製品モードでSwagger、ReDoc、OpenAPIを無効化する
- [x] 境界値、大容量JSON、連続呼出しのテストを追加する

## 受入条件
想定外のOrigin、フィールド、サイズ、頻度の要求を処理前に拒否する。

## テスト
正常上限と上限超過、未知フィールド、CORS preflight、製品モードの404を確認する。

## 実装メモ
- リクエストボディ上限は32 KiBで、`Content-Length`がない分割受信も累積して拒否する。
- 全体同時実行は8件、高コスト処理は2件までとし、`resolve`、`check`、`ollama/warmup`へ1分窓の頻度上限を設ける。
- Chrome拡張はmanifestの公開鍵でIDを固定し、そのOriginだけを既定CORS許可対象とする。
- `CLARITH_MODE=development`を明示した場合だけSwagger、ReDoc、OpenAPIを有効にする。
