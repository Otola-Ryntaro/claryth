# 034 臨床警告UI・アクセシビリティ改善

## 目的
レビュー状態、重大度、根拠を読み落としにくくし、臨床利用不可の状態を誤認させない。

## 対象外
医学データの承認と画面全体のデザイン刷新。

## 依存
029。031の検証状態も表示対象とする。

## タスク
- [x] 状態コードを日本語の利用可否と理由へ変換する
- [x] 未承認・署名不正・期限切れ警告を画面上部へ常時表示する
- [x] 重要情報を12px以上へ引き上げ、色以外でも状態を識別可能にする
- [x] 全操作へ明瞭なキーボードフォーカスを付ける
- [x] 200%ズーム、狭幅、強制カラーモード向け実装と静的検証を行う
- [ ] Windows実機で高コントラスト、Tab順、スクリーンリーダーを確認する
- [x] UI状態の自動テストとChrome実機確認を追加する

## 受入条件
利用者が判定前に臨床利用可否を理解でき、キーボードだけで主要フローを操作できる。

## テスト
未承認、承認済み、DB障害の各画面とWCAG 2.2 AA相当の主要項目を確認する。

## 実装メモ
- 上部の利用状態は常時表示し、`判定利用可`、`臨床利用禁止`、`判定利用不可`を見出しと理由で示す。
- 期限切れ、署名不正、DB変更・破損、ファイル欠落をそれぞれ日本語の対処案へ変換する。
- 状態変化は`aria-live`、エラー状態は`role="alert"`、正常状態は`role="status"`で通知する。
- 重要情報は最小12px、状態バッジは枠線と文言を併用し、色だけへ依存しない。
- 全操作に3pxの`:focus-visible`輪郭を付け、`forced-colors`向けルールを追加する。
- 320px幅と200%ズーム相当の240px実効幅で横スクロールなし、警告・入力・主要ボタンの欠落なしをブラウザ確認した。
- UI状態5件、HTML/CSSアクセシビリティ契約4件を自動テストする。

## 実機チェック
Chrome拡張として読み込んだ状態で、Tab/Shift+Tab順、Windows高コントラスト、NVDAまたはWindowsナレーターの読み上げを035の出荷E2Eでも再確認する。
