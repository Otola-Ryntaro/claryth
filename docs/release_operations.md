# くらりす リリース運用手順

## 出荷禁止条件

次のいずれかが未完了なら製品版として出荷しない。

- 製品責任者、医学データ責任者、セキュリティ窓口の実名と連絡先が承認記録にない
- 016の医学レビュー済みDB生成と全承認レコードのゴールデンテストが未完了
- DBの`review_status`が`clinically_reviewed`ではない、またはレビュー者・日時・承認IDがない
- 署名、全テスト、依存監査、SBOM、Windows 10/11実機E2Eのいずれかが失敗または未記録
- PMDA原資料・抽出データの院外再配布について法務または権利者確認が完了していない

評価版は`--allow-evaluation`で生成できるが、臨床利用禁止表示を解除してはならない。

## 責任者

リリースごとにチェックリストへ次を実名で記録する。兼務する場合も各責任を個別に承認する。

- 製品責任者: 出荷可否、利用施設、配布先、撤回判断
- 医学データ責任者: PMDA差分、レビュー完了、承認期限、緊急安全性情報
- セキュリティ窓口: 脆弱性監査、署名鍵、インシデント、SBOM
- 配布担当者: 配布物ハッシュ、導入記録、回収・ロールバック

責任者未割当のリリースは承認不可とする。

## 更新頻度

- PMDA更新確認: 毎週1回、および緊急安全性情報・安全性速報の通知時
- 通常データリリース: PMDA差分の医学レビュー完了後。少なくとも月1回、更新有無を記録
- セキュリティ監査: リリースごと、およびHigh以上の新規アドバイザリ通知から1営業日以内
- 医学承認期限: 承認日から30日、または対象電子添文の改訂検知時の早い方
- 署名manifest期限: 30日以内。期限更新だけでも再承認と再署名を必要とする

## 配布物作成

1. オフライン管理された秘密鍵を使用できる署名端末で全テスト・監査・SBOMを完了する。
2. `python scripts/build_release_bundle.py --release-id <ID>`を実行する。未承認DBでは失敗する。
3. 評価版だけは`--allow-evaluation`を使用し、配布名と記録へ評価版と明記する。
4. ZIP、`.manifest.json`、`.manifest.sig`、`.public.pem`の4ファイルを一組で配布する。
5. 配布先は展開前に、別経路で受領した公開鍵SHA-256を指定して検証する。

```powershell
python scripts/verify_release_bundle.py <bundle.zip> `
  --expected-public-key-sha256 <承認記録のfingerprint>
```

検証スクリプト自体も管理済みソースまたは前版の検証済みbundleから取得する。公開鍵fingerprintとZIP SHA-256は、ファイル送付とは別の院内変更管理記録で通知する。

## 導入

1. 署名済みbundleを検証してから新しいフォルダへ展開する。既存フォルダへ上書きしない。
2. `powershell -File scripts/install_release.ps1`を実行する。
3. Chromeへ`extension/dist`を読み込み、画面上部の利用状態を確認する。
4. 製品版は「判定利用可」、評価版は「臨床利用禁止」でなければ導入失敗として扱う。
5. E2E記録票を保存し、端末、OS、Chrome版、bundle IDを紐付ける。

## 緊急停止

1. 製品責任者または医学データ責任者が利用停止を宣言し、対象release IDと理由を記録する。
2. 配布担当者は利用者へ「くらりすを起動・使用しない」旨を連絡する。
3. 各端末でAPIを停止し、`backend/data/release_manifest.sig`を隔離する。APIは完全性エラーで判定停止する。
4. 必要時は`uninstall_windows_launcher.ps1`を実行し、Chrome拡張を無効化する。
5. 原因、影響期間、対象端末、利用記録の有無、再開条件を監査記録へ残す。

## ロールバック

- ロールバック先は、署名有効・期限内・医学承認有効な過去bundleだけとする。
- 現行フォルダを保持したまま過去bundleを別フォルダへ展開し、署名検証後に再導入する。
- DBだけ、コードだけ、拡張だけの部分ロールバックは禁止する。
- ロールバック後に正常、未承認、改変DB、ポート競合、Ollama停止のE2Eを再実施する。

## 監査記録

最低限、release ID、各責任者、承認日時、PMDA確認日、DB approval ID、ZIP SHA-256、公開鍵fingerprint、SBOM、監査結果、対象端末、導入・撤回・ロールバック履歴を保存する。
